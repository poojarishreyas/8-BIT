01 The problem

Same meaning, 6.91× the tokens. Kannada speakers pay a tax on every answer.

Open models cut Kannada into byte-sized pieces. That multiplies the cost, the latency and the context each Kannada answer uses. The R3 challenge: reduce the cost gap for an Indian language, and measure exactly what the improvement costs.

Hypothesis. Most of Kannada's token tax comes from pre-tokenization, not vocabulary size. A mark-aware, akshara-safe, suffix-aware extension of Qwen3's BPE cuts the Kannada-to-English ratio by more than half compared with a standard BPE extension of the same size, and leaves English, JSON, code and tool calls untouched.

02 Method

Three layers on an append-only extension of Qwen3

We keep every Qwen3 token, merge and ID, and append new Kannada merges from ID 151,669. Only merges that contain Kannada bytes are added, so English can never change. Each layer is one ablation step.

L1

Mark-aware split rule

Qwen3's split rule \p{L}+ cuts vowel signs and virama out of words. We use [\p{L}\p{M}]+, plus ZWJ/ZWNJ only right after a Kannada character.

L2

Akshara units

Merges build each character from its bytes, then each akshara, then merge only whole aksharas. Rules come from akshara-tokenizer (regex \X splits conjuncts like ಕ್ರಿ).

L3

Suffix-aware

Hard stem | suffix boundaries from a seed list of case endings (ಯಲ್ಲಿ, ಗೆ, ಯಿಂದ …), so merges never cross them. Learned with the parity-aware-bpe learner.

Data hygiene

  • Training: Sangraha verified + Kannada Wikipedia, 15M + 15M characters. English reference 30M characters, no English merges added.
  • Test (never trained on): FLORES-200 devtest 1,012 · IN22-Gen 1,024 · Belebele passages 488.
  • Romanized test: IndicXlit (beam 4) on all three sets, 0 failed lines.
  • Kanglish test: 181 everyday sentences with English translations, checked by a native speaker.

Two traps we hit and fixed

  • HF tokenizers renumbers added tokens when the vocab has an ID gap. Special tokens now stay at their original IDs.
  • In transformers 5, Qwen2Tokenizer rebuilds Qwen's split rule and silently undoes ours. We export with PreTrainedTokenizerFast and verify against tokenizer.json.

04 Romanized Kannada & Kanglish

Kannada script is now half the cost of the same text romanized

On Qwen3 the opposite was true. Latin text is untouched by design (to keep English identical), so romanized Kannada stays at 2.17× and Kanglish at 1.13× for every Qwen3 variant. Real chat Kanglish is short and full of English words, so it was already cheap.

08 Limits & hand-off

What it costs, and what is next

Limitations

  • Layer 3 costs about 4.5% more tokens than layers 1–2; in exchange, case endings stay separate tokens.
  • Latin text is untouched to keep English identical, so romanized Kannada and Kanglish get no gain.
  • Unseen aksharas still split: 282 of 155,165 in the test sets, all out of inventory.
  • The retrained model loses 7–17 points on English and general-knowledge benchmarks.

Hand-off
